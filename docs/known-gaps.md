# 已知缺口（Known Gaps）

按「影响使用」排序。每条都写明**现象**、**当前行为**、**补齐时机**。

---

## 1. 安全验证只支持短信码，交互式验证码（腾讯/极验/滑块）未实现

- **现象**：账号触发酷狗风控时，会出现「本次操作需要『腾讯验证码』，当前版本尚未支持该验证方式」。
- **当前行为**：给出明确提示并提供**取消**。取消会释放被挂起的请求并返回可读错误，
  不会让请求一直挂死。已支持：短信验证码（输入+提交）、登录确认、绑定手机号/实名/风控的告知。
- **影响面（实测）**：登录、以及**创建一起听房间**都会触发风控。
  加入别人的房间、听歌、搜索、收藏等不受影响。
- **为什么没有一起做**：桌面实现 764 行（第三方 SDK 脚本加载 + iframe 定位 + 残留 DOM 清理），
  且严重依赖桌面窗口布局；照搬到触屏上是负收益。
- **补齐时机**：P1。做法是在 `src/mobile/components/VerificationSheet.vue` 里按 provider 分支，
  加载对应 SDK 并在 App 内嵌 WebView/iframe 中承载；内核侧状态机（`@/utils/kugouVerification`）已就绪，不需要改。

## 2. 播放链路已接线，但**完整验证需要真实登录**

- **已完成**：
  - `src/mobile/adapters/player.ts` 适配层（启动引导 / 只读状态 / 操作），页面不直接读内核 store
  - 底部圆钮接真实封面与播放态；全屏播放页 `/player`（封面 + 进度拖动 + 传输行 + 队列面板）
  - 首页点歌→入队→播放已接通（点击后有可读错误提示，不是静默无响应）
  - 启动页新增「恢复播放状态」步骤（水合队列/历史 + `player.init()`，
    后者负责注册系统媒体控制回调，晚注册会丢通知栏事件）
- **已验证**：原生播放链路（Media3 → AudioTrack）用本地合成的 WAV 走通：
  `load` 返回 `duration = 5`、`play` 后 `timePos` 从 1.936 推进到 3.432（真实在放）。
  工具：`node scripts/dev/serve-audio-fixture.mjs`（现场合成 5 秒正弦波 WAV，
  不依赖任何外部 URL —— 实测 Google 的 ExoPlayer 测试音频域名在当前网络下 HTTPS 被重置）。
- **未验证**：`/song/url/auth/merge` 需先用假 token 从 `getUserVerify()` 取 `auth`，
  所以**真实出声那一公里必须用真账号验证**。
  用伪造登录态点歌会得到内核的「歌曲不支持」提示（预期行为，已确认错误链路可读）。
- **验收入口**：登录后在首页点一首歌，确认：
  ① 出声；② 进度条与时间走动；③ 通知栏出现播放控制且能暂停/切歌；
  ④ 杀进程重启后播放状态恢复。

## 3. 主界面布局未做自动化验证

- **现象**：`pnpm verify:layout` 只覆盖**未登录可达**的页面（启动页、登录页）。
- **原因**：主界面需要登录态；无头 Chrome 里设备注册与鉴权都会失败。
- **当前替代**：
  - 真机：`bash scripts/device-forward.sh` + `pnpm verify:device "..."`
  - 伪造登录态：向 localStorage 写 `echo.mobile.kv.pinia:user`
    （`{ info: { userid, token, nickname }, isLoggedIn: true, savedAccounts: [...] }`）
    再 reload，即可进入主界面（接口会报错，但布局/错误态/播放页可验）。
    本文档中多个结论（时长单位、图标空 svg）就是靠这个方式发现的。
- **补齐时机**：P1。把它产品化成 `verify-layout.mjs --fake-login`
  （用 CDP `Page.addScriptToEvaluateOnNewDocument` 预置状态）。

## 4. 未实现的功能入口一律不展示

设计原则：**不铺一排点了没反应的图标**。当前未接入的入口只有两种状态 ——
要么不存在，要么明确标注「即将开放」。因此现在「我的」页只有收藏/历史两条带标注的占位，
排行榜、听歌识曲等磁贴标注「即将支持」。

## 5. 1.4MB API bundle 首屏一次性加载

- **现象**：冷启动需要解析 ~684KB（minified）的 KuGou API 产物。
- **当前行为**：可接受（实测构建产物分块后首屏 ~1MB minified / ~300KB gzip），暂未优化。
- **补齐时机**：P5。按路由分组拆包 + 动态 import。

## 6. 应用图标仍是 Capacitor 默认图标

- **补齐时机**：P5（打包与发布阶段）。

## 7. 弹幕只能看，不能发；分享不做

**弹幕**（已在播放页实现：开关 + 滚动显示 + 字号/速度/不透明度/密度）

- **发送未做**：要走 `comment/song-barrage/send`。它产生的是**公开内容且需审核**，
  服务端审核中返回的弹幕列表可能是空的（旧项目为此专门做了"保留当前播放池"），
  验证成本高且会给账号留下公开记录。
- **只做『看』的原因**：内核 `utils/barrage.ts` 已提供轨道分配与飞行时长算法，
  展示层的成本可控；发送则是另一套（输入 + 审核回流 + 本地先行上屏），单独评估。

**分享**（不做）

- 内核的分享链接指向**旧项目自己的网页落地页**（`SHARE_WEB_BASE_URL =
  https://hoowhoami.github.io/EchoMusic/share/`，写死在 vendor 的 `shared/share.ts`，
  改不了），分享出去的内容带的是 EchoMusic 品牌，与本项目对不上。
- **结论**：与其带一个对不上的品牌，不如不提供入口（符合"不铺点了没反应的入口"）。
  原生侧 `EchoShare.share` 仍在（接收入口 `shareOpen` 要它），只是没有主动分享入口。

## 附：已处理的上游行为

### `/register/dev` 偶发返回空 `data`

- **现象**：首次请求偶发返回 `{status:1, error_code:0, data:[]}`（`data` 是空数组而非 `{dfid}`）。
  内核的 `ensureDevice` 把它当失败且不重试，用户看到「设备注册失败」错误页 —— 其实再等一下就好。
- **已处理**：`LoadingPage.vue` 在 UI 层补了一次自动重试（间隔 800ms），不改内核。
  实测重试即成功（一次冷启动实测中复现并验证）。
