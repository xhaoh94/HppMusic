## 播放页队列抽屉：复用 SongRow + 打开时定位当前曲目

**改动**：`src/mobile/features/player/PlayerPage.vue`

- 队列项从自绘 `<button class="queue-item">`（只有序号 + 歌名 + 歌手）换成
  `@mobile/components/SongRow.vue` —— 与外面所有歌曲列表同一份组件，
  高亮即外面那套：`--accent-soft` 整行底色 + 歌名 `--accent` + 三条跳动音量柱 + 封面/时长。
- `currentQueueIndex`（比 `song.id`）换成 `currentSongKey = songKeyOf(track)`，
  与 SongRow 写到 DOM 的 `data-song-key` 同一套规则（mixSongId → hash → id）。
- 打开抽屉时把当前曲目滚到视口中间（`watch(queueOpen)` → `nextTick` → `rAF`）。

**两个实现要点**（都写进注释了）：
- 定位用 `data-song-key` 找行，不按 `index × 行高` 算 —— 行高会被音质标签/序号撑变。
- 用 `getBoundingClientRect` 差值调 `scrollTop`，不用 `offsetTop`：`.sheet-body`
  和 `.sheet-panel` 都不是定位元素，`offsetTop` 会算到 `position: fixed` 的遮罩上；
  另外进场动画期间两者被 translateY 同步平移，差值不受影响，所以能在动画开始前就滚好
  （等动画结束再滚会先看到列表顶部再被拽走）。

**样式对齐**：`SongRow` 自带左右 16px 内边距，抽屉内容区已有 20px。
`.queue-list { margin: 0 calc(var(--sp-5) * -1) }` 拉满 + `:deep(.song-row)` 把左右内边距
改回 `--sp-5` → 高亮底色铺到抽屉边缘，序号/封面与标题左对齐。

**验证**（无头 Chrome + CDP，脚本 `/c/Users/xhaoh/AppData/Local/Temp/shot-queue.mjs`）：
用 `localStorage['echo.mobile.playbackSnapshot']` 水合 30 首队列（真实水合路径，
不需要登录/真能播），当前曲目放第 22 首。实测：`rowCount=30`、`activeIndex=21`、
`playingBars=3`、`activeBg=rgba(52,211,153,.16)`、`firstRowPadding=20px`、
`scrollTop=960`、`activeOffsetFromCenter=0`（正好居中）、`activeInView=true`。
截图 `.workbuddy/queue-dark.png`。

**环境坑**：
- Bash 工具里 `(cmd &)` 起的进程在本次调用结束就被回收 —— 预览服务器要
  `run_in_background: true` 起才活得下来（否则后续 curl 全 502）。
- 截图脚本里 WebSocket 会让 node 不退出，必须加超时看门狗，否则看起来像"卡死"。
- 无头 Chrome 的调试端口如果上一次被 SIGTERM 杀掉没清理，端口仍被占用，
  新实例绑不上，脚本会连到旧的 about:blank 上一直等 —— 先 `Get-NetTCPConnection` 查再 kill。
